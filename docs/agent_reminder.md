## 一、评审发现

### 1. 腿链平面锁死（几何事实，非风格问题）
- 证据：髋孔在 y=±30（`cad/pelican_skeleton.py`）；脚踏踝销在 y=±16（`cad/drivetrain.py`）；大腿/小腿为直连杆，两端销孔平行 Y 轴且共面（`cad/legs.py` 的 `link()`）。
- 事实：直连杆两端销必须共面。运动链 髋(30)→膝→踝(16) 无解，按图装配锁死。
- 为什么现有检查没抓住：`scripts/total_assembly.py` 的 `place_leg` 把连杆当线段用四元数指向，膝点 y 浮在两平面之间，平面约束被仿真抽象抹掉；`m2_sanity.py` 只核了髋-脚距离可达（7–11cm），未核共面；checklist D 区"运动学扫掠干涉检查"未做。

### 2. 转向链三处缺口
- M2 §3.3"MG90S 装头管"与头管几何矛盾（转向孔 φ12，MG90S 宽 22.8mm）；`cad/frame.py` 无舵机座；`scripts/total_assembly.py` 里舵机悬空无承载。
- M2 说"经推杆转前叉"，推杆无 CAD 零件、无 BOM 条目。
- 车把：`cad/fork.py`、BOM、手册、清单均无，也没有"无车把、纯舵机转向"的设计声明。

### 3. 固件交互承诺与实际行为相反
- 页面按钮只在 touchstart/mousedown 单次 fetch；固件 800ms 看门狗无指令即强制停车回中（`electronics/firmware/src/main.cpp`）。实际行为：按住约 0.8s 自停，需连续点按。页面文案与手册 §7 均承诺"按住走、松开停"。固件编译验证过，浏览器交互未实测。

### 4. 定制 PCB 无可制造文件
- `electronics/pcb_carrier.md` 自称"可直接落板的完整设计输入"，文末"Gerber 由嘉立创EDA专业版按本设计导出（M5 制造包收口）"——仓库无 EDA 工程亦无 Gerber；BOM 已列 ¥20 定制 PCB；手册 §3 让 Cindy 焊到对应位号。Cindy（11 岁设定）无法从设计说明画出板子。

### 5. 承诺与兑现、台账状态
- M2 §7 承诺"关键件手算应力""转向扫掠干涉检查"：无脚本、无结果落档。
- `docs/completeness_checklist.md`：功率预算（脚本已存在且 ≈2.4h 已写入 G 区）、配合公差表（params.py FIT 表已存在）、刷固件路径（手册 §6 已存在）已完成但仍为 `[ ]`；真未做的（打印备件、转向限位、装配扫掠）混在其间。台账当前无法区分"已做未销"与"未做"。
- M2 §6.1 写 WebSocket，实现是逐事件 HTTP GET，漂移未声明。

### 6. 次要事实
- 助学轮几何离地 8mm（轮心 z=38、半径 30），M2 写"倾斜接地"、手册写"轻触"，实际两者都不是。
- 头管实体轴线（HB→HT，11.3°）与转向孔轴线（13.8°）差约 2.5°，孔在头管内偏漂，最薄壁约 1mm。
- 训练轮臂 Box 与车架板咬合仅 7mm 深。
- `pelican_bike.ino` 与 `src/main.cpp` 为双份拷贝，目前内容一致（差一个 include 与换行符），属双源。
